# 第二题：投资事件情报与证据时间线

## 验收对照

|题目要求|实现与验证|
|---|---|
|同一事件识别合并|AI提取六位标的、事件类型、原方案日期；用户检查修改；确定性三元组归档。无锚点阻止提交。同标的新计划另建。文件哈希/ID去重。|
|版本演化|逐份导入五份真实公告。每版保存完整快照、字段前后值、来源ID、更新时间。历史查看与导出。逆序导入不覆盖较新披露。|
|事实/观点/推测/传闻及权重|四类语义标签；权重5/2/1/0为研究优先级，不是真实性概率。用户提交核验前均0。观点不更新确认事实。同源副本不增加独立支持。|
|证据冲突|模拟区S03/S05同日已核验材料结论相反，展示双方引用，标为冲突，停止单一结论；历史数值变化不误标冲突。|
|发生/披露/抓取/更新|证据抽屉逐项展示；日精度中国标准时间不补造时分秒；实际采集UTC、工作区实际入库UTC、实际结论更新UTC分列。未知披露时间保留未知。|
|更新/否认/更正/过期及通知|真实进展更新；隔离模拟S01→S02否认→S03更正，原证据不删除；评估时钟跨有效期后失效并生成通知；取消关注停止新通知，重复材料不重复通知，通知已读持久化。|
|最初来源与标的关系|显示最早已收录原始公告及其PDF页码，不宣称全网最早；主体直接关联与可能财务/股本路径，回链个股诊断；演练推测另列间接影响，不推断收益因果。|
|可运行Web与仓库|`/events`，与诊断共用同一产品，README可复现。现有站点受限访问，对外评审需站点所有者开放。|
|视频/AI记录/测试|见EVENT_DEMO、EVENT_AI_USAGE、EVENT_TESTING。|

## 真实证据边界

仅五个手工核验节点；没有将公告间所有中间变更补造为完整时间线。R03价格上限相对R01已变化，中间调整未收录。R04为权益分派后的调整，非更正错误。R05明确只是拟注销，故仍显示注销结果待核验。

初始工作区只入库R01，其他已核验历史资料在收件箱等待导入。这是历史回放，不是今天的完整当前资讯或后台监控。每个浏览器通过HttpOnly随机cookie隔离D1工作区；不读持仓、身份信息。无跨设备账号同步、邮件、短信、自动后台抓取；手动导入触发站内通知。
