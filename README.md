已实现第一题个股诊断及第二题投资事件情报两条主链路，选取贵州茅台（600519.SH）。第三题自然语言选股待实现。第二题入口 /events，覆盖真实公告版本演化及隔离异常演练。

产品网址：https://evidence-stock-diagnosis.eva000.chatgpt.site （默认访问受限；对外提交前需授权开放）

源码仓库：https://github.com/during000/zhiheng-stock-diagnosis

## 目标用户与核心任务

面向希望理解公司现状、愿意核对原始材料的个人投资者与研究人员。用户输入研究问题，检查或修改诊断维度，生成解释；查看事实、推断、矛盾和未知；点击证据查看原始字段、单位、公式、财报页码和披露时点，继续追问并导出研究记录。

## 运行

Node.js >=22.13，npm。

```sh
npm ci
cp .env.example .env
# 在本机编辑 .env，配置自己的 OPENROUTER_API_KEY
npm run dev
```

打开终端输出的本地地址。没有模型密钥也能查看全部核验数据、确定性计算与证据卡，界面明确显示模型未配置。密钥仅服务端读取，禁止加 NEXT_PUBLIC_ 前缀。

```sh
node --test tests/engine.test.mjs
# 本地服务运行后：
node --test tests/api.test.mjs
npx tsc --noEmit
npm run build
```

开发与发布沿用 Sites 的 Vinext / Cloudflare Workers 运行方式。部署时将 OPENROUTER_API_KEY 配为服务端 secret；LLM_MODEL 默认为 google/gemini-2.5-flash。`.openai/hosting.json` 仅保存项目身份与逻辑数据库绑定，不放密钥。模型经 OpenRouter 调用，只传研究问题及公开证据，不上传用户画像或持仓。

## 核心设计与 AI 分工

- 公司框架：品牌消费 / 白酒，含财务子公司。因此关注毛利、渠道与预收货款，合并经营现金流需修正解释，不能套用单一回款评分。
- 维度选择：根据问题进行可检查的规则路由；用户手动修改优先。LLM 根据所选维度与公司类型解释选择理由。
- 确定性引擎：`lib/engine.mjs` 计算同比、毛利率、渠道占比、TTM利润、PE、样本收益、最大收盘回撤与年化波动率。LLM 无权修改原始数据或计算数值。
- AI：`app/api/diagnose/route.ts` 实时生成条件性分析及待验证问题，只允许推断/未知类别，必须引用当次证据ID。结构、引用、数字和部分合规模式不符时丢弃输出，明确提示失败并保留证据。
- 证据表达：卡片独立标明知识类型与正面/负面/矛盾/未知证据；不产生综合好坏分数或买卖建议。
- 数值溯源：每条关键证据有来源、期次、原始输入、单位、计算公式、PDF页码和抓取时间；可打开原始PDF。资料库保存文件SHA-256用于版本核验。
- 研究延续：财务期次、假设价格敏感性、真实历史行情、两家同业比较、事件与未知问题、追问、JSON导出。

## 数据来源与时点

数据快照版本见 `data/evidence.json`。资料抓取于2026-10-07；财务最新期间为2026年上半年，行情最新样本为2026-09-30。不是实时行情，也不承诺截止运行日已覆盖全部公告。

1. 贵州茅台公司官网2026半年报（披露2026-08-15，未经审计），以及2025年报（披露2026-04-17，标准无保留意见）；年报比较表提供2023—2025年度值。
2. 巨潮资讯：五粮液、泸州老窖2026半年报；同业仅比较相同半年期合并营业收入与归母净利润，不做完整行业排名。
3. 腾讯财经公开日线接口：前复权收盘价；只使用诊断需要的公开样本字段，未使用供应商的黑盒评分或预测。此替代接口缺少稳定性保证。
4. 扶摇官方文档已核对，服务要求账号签发API Key；本次没有可用授权。iFinD MCP未连接。未伪称使用这些服务，未抓取受限接口或受限数据。

公告披露日来自公司财报索引/披露平台，不用PDF文件路径日期替代；抓取时间不等于披露时间。年度与半年分开比较；合同负债对比上年末，不称同比；营业收入与含利息收入的营业总收入不混用；直销占比采用酒类主营业务分母。

原始字段人工核验后提交，`scripts/build-evidence.py` 为开发时的数据整理记录；它不会解析新财报或保证自动更新。若刷新行情或更换PDF，必须重新核验时点、提取字段、SHA和测试后提交新版本。生产“生成诊断”只更新分析，不刷新数据。

## 边界与未做事项

- 只诊断指定A股；未实现多标的检索、自然语言选股或事件去重/合并/推送。后两题另行开发。
- 不支持银行等其他公司框架；未接入扶摇、iFinD、定时刷新、公告全文自动抽取、实时新闻监控、研报观点融合。
- 历史估值分位、一致预期、终端动销、经销商库存缺失，显示未知；PE不等同合理价值。
- 期末股本用于近似PE；未考虑报告后股本变化。前复权历史序列由供应商计算；年化波动基于252个交易日约定，非未来波动预测。
- 词法与结构校验不能证明LLM推断正确，不能覆盖所有提示注入或所有金融合规表达。引用有效不代表事实蕴含关系成立，关键解释需人工复核。
- 本地与公开行情样本是快照；无自动过期刷新。页面始终显示资料日期，并提供模拟过期阻断场景。真实运行超过资料有效期时应更新快照或仅用于历史研究。
- 未实现服务端限流、付费额度管理、用户系统及持久化研究记录。仅导出到用户本机，不上传持仓或画像。默认Sites部署有访问限制，外部评审需单独开放访问或使用自己部署。

## 第二题：投资事件情报与证据时间线

面向需追踪投资事件的个人研究者。访问 /events，导入五份真实公告，检查同一事件的版本、字段变化、四类时间、原始凭据与通知；AI提取用户材料，可修改归属后归档为未核验材料。

数据：贵州茅台临2024-025、临2025-001/013/025/032。data/events.json保存URL、页码、SHA和采集时点。历史回放，非实时完整资讯；拟注销不等于已注销。隔离模拟标的SIM001验证否认、更正、冲突、时效，不是现实公司。

核心：lib/events.mjs确定性归档；app/api/events/analyze实时模型提案。D1按HttpOnly随机cookie隔离浏览器工作区；刷新可恢复，乐观版本检查避免并发覆盖。无跨设备同步、后台监控、自动来源核验、邮件推送或任意URL抓取。扶摇/iFinD尚无授权，用户材料通过OpenRouter处理。AI不能提高来源权威性，未核验材料权重为零。

首次运行数据库：先npm run build，再按顺序应用未执行的迁移（不要重复执行）：

```sh
npm run dev
node --test tests/events.test.mjs
# 本地服务启动后，设置实际服务端口
EVENT_BASE_URL=http://127.0.0.1:8787 node --test tests/events-api.test.mjs
```
